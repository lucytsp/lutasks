# Task Wall — working notes

A colour-coded front end for Google Tasks, served from Google Apps Script.
Single HTML file, no build step, no framework.

This file is the plan. Copy it into any Apps Script project of the same shape.

---

## The four copies

There is no sync anywhere in this chain. A person moves the code at each step.

    Claude's container  →  GitHub  →  your Mac  →  Apps Script project
                git push     git pull    clasp push

Only GitHub and your Mac persist. A Claude session's container is wiped when
the session ends, so **commit and push after every working change** — not at
the end. Unpushed work is lost work.

The Apps Script project is a separate copy that git knows nothing about. If
anyone edits in the browser editor, `clasp pull` before the next push or that
edit is silently overwritten. (This is exactly how `Code.gs` and `Code.js`
ended up contradicting each other in an earlier repo.)

## Config split — two rules that will break things if broken

**1. Never commit `Config.gs`.** It holds colleagues' names, email addresses
and internal list titles. `Config.example.gs` is the shared one; keep it
generic. On a fresh clone: `cp Config.example.gs Config.gs`.

**2. `.claspignore` must exclude `Config.example.gs`.** Both files declare
`const CONFIG`. Push both and Apps Script throws a redeclaration error and the
*entire script* fails to load. That exclusion is load-bearing, not tidiness.

## Deploying

```bash
./deploy.sh                    # push only
./deploy.sh "what changed"     # push, then publish
```

**Always redeploy over the existing deployment id** (`clasp deploy -i <id>`),
which `deploy.sh` does from `.clasp-deployment`. A bare `clasp deploy` mints a
*new* deployment with a *new* `/exec` URL every time. Do that three times and
colleagues are bookmarked to the first one, frozen at whatever shipped that
day, while you are convinced you deployed the fix.

Publishing requires an explicit message, so a mid-edit push cannot go live.

## Before claiming anything works

This project has a history of confident wrong answers. Each rule below comes
from one.

- **Read the reference, not your memory.** Every API belief that was checked
  turned out to have a caveat attached. Ask for the docs if they cannot be
  fetched.
- **Read the whole page, not the paragraph you came for.** Reading
  `tasks.list` for pagination and stopping missed `showAssigned` three lines
  below, which was silently dropping data. Constraints on a field matter more
  than whether the field exists.
- **Assert on pixels for visual bugs.** A test that checked
  `getComputedStyle(...).strokeDashoffset` passed while the bug was plainly
  visible in a screenshot. Screenshot it and look.
- **Never hardcode counts in tests.** `=== 4` lists, `=== 1` toast button.
  Every one broke on the next feature and reported a regression that was not
  one. Derive from state, or locate by text.
- **Re-check environment capabilities, never cache them.** `google.script.run`
  was captured once at parse time; the Apps Script sandbox injects it
  asynchronously, so on a real deployment it latched to `false` and the app
  silently served sample data and saved nothing.
- **A silent fallback is a bug.** Falling back to demo data is right for a
  standalone preview and wrong for a deployment. Distinguish the two and say
  so on screen.
- **Ask for the cheap discriminating fact first.** "What URL are you on?"
  would have settled the above in one line. Once you have a theory you will go
  looking for evidence that fits it.
- **Test fixtures are code and have bugs.** Suspect the fixture before the
  feature.

## Google Tasks API traps

- Three `tasks.list` defaults drop data silently: `maxResults` 20 (max 100),
  `showHidden` false — and tasks completed in Google's own apps are *hidden* —
  and `showAssigned` false. Set all three and follow `pageToken`.
- `position`, `parent`, `hidden` and `links[]` are all **read-only**.
  Reordering goes through `tasks.move`, not a patch.
- `links[]` cannot be written, so a task can never be *copied* between lists —
  the copy would lose its link back to the original email. Use
  `tasks.move` with `destinationTasklist`.
- Repeating tasks **cannot** be moved between lists. It is the one documented
  failure of that call.
- `due` is a *scheduled date*, not a deadline, and the time is discarded.
- Notes cap at 8,192 characters, titles at 1,024. Anything that appends to
  notes must check first.
- Tasks assigned from Google Docs cannot carry notes at all.
- Apps Script advanced-service signature order: **request body, then path
  parameters in endpoint-URL order, then an optional-parameters object** — and
  any category the method lacks is omitted entirely. `tasks.move` has no body,
  so it is `move(tasklist, task, opts)` and not `move(body, ...)`.
